# Contributing

Use focused branches and commits that explain a real change. Keep tests and docs
beside the behavior they verify. Do not manufacture historical activity or add
empty commits to meet a count.

Run core tests, the demo and offline notebooks. Describe optional checks not run.
Add regressions for new failure modes rather than tests that only mirror code.
Never attach raw social-media records, participant identities or secrets to issues.
Use fictional minimized examples. Report methodological limitations alongside results.
